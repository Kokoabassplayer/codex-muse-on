# Persist Enabled state after setup

Codex Muse-On will persist a user's one-time Enabled opt-in across launches so login start does not require a per-session activation click. Shortcut dispatch remains an ephemeral Active state gated by the exact Muse-On connection, required permissions, and Codex being foreground; any failed gate sends nothing, and Disable and Quit remain available. Denying a required control permission during First Enable preserves Enabled as `Inactive — Permission Required` without recurring or automatic prompts. The installation makes at most one responsible-app permission request, during First Enable or the first explicit user-initiated Retry needed to migrate an existing setup; later retries only recheck and guide to Settings. Disable cancels the intent, and login, relaunch, and routine gate changes never request permissions. This trades per-session confirmation for low-friction behavior while retaining fail-closed dispatch gates, and supersedes the earlier per-session activation requirement for the next application phase.
